Job satisfaction by income and gender

Source: R/data-satisfaction.R
satisfaction.Rd

Job satisfaction, income and gender of 110 workers, one row per person. The data are not simulated: they come from a table of 1991 General Social Survey data published by Agresti (2002, Table 7.8), expanded to one record per respondent. One case was added to each of the table's six empty cells, so there are 110 rows instead of 104.

Usage

satisfaction

Format

A tibble with 110 rows and 3 variables.

gender

Gender. Values: F = female; M = male. Type: character. One row per respondent, expanded from a published table.

income

Income. Values: 1 = less than $5,000; 2 = $5,000 to $15,000; 3 = $15,000 to $25,000; 4 = more than $25,000. Type: integer. Ordered income categories.

satisfaction

Job satisfaction. Values: 1 = very dissatisfied; 2 = a little dissatisfied; 3 = moderately satisfied; 4 = very satisfied. Type: integer. From a published 1991 GSS table (Agresti 2002, Table 7.8), not simulated as v0.2.0 said. One case was added to each of its 6 empty cells, so n = 110 instead of 104. Category 2 keeps the source Stata file and 1991 GSS SATJOB wording (a little dissatisfied); Agresti (2002, Table 7.8) and coin::jobsatisfaction print it as A Little Satisfied.

See codebook("satisfaction") for this table as a data frame.

Source

Agresti, A. (2002). Categorical data analysis (2nd ed., Table 7.8). Wiley. Data: 1991 General Social Survey. https://cran.r-project.org/package=coin

Individual-level expansion of the published table made for the UC Berkeley EDUC 275B course; the same table is on CRAN as coin::jobsatisfaction. Provenance: probable.

Details

satisfaction runs from 1 = very dissatisfied to 4 = very satisfied, and income has four ordered bands, from 1 = less than $5,000 to 4 = more than $25,000. Both are stored as integers: wrap the outcome in factor() for an ordinal model, and enter income either as a score (one slope) or as factor(income) (three contrasts). gender is text, so a model formula turns it into a factor with women ("F") as the reference level. There are no missing values. Note on category 2: this package keeps the label "a little dissatisfied" from the source Stata file and the 1991 GSS SATJOB item, whereas Agresti (2002, Table 7.8) and coin::jobsatisfaction print category 2 as "A Little Satisfied".

The six added cases fill the empty cells of the published table: one each for women in income bands 3 and 4 and for men in bands 2, 3 and 4 with satisfaction = 1, and one for men in band 3 with satisfaction = 2. All six are in the two lowest satisfaction categories and in income bands 2 to 4, so they weaken the association between income and satisfaction: in the proportional odds model of the examples, the income coefficient is about 0.34 with them and about 0.51 without them. Results therefore differ from those for Agresti's original 104 cases. Even so the data are sparse: 23 of the 32 gender-by-income-by-satisfaction cells hold three cases or fewer.

Version 1.0.0 changes no values. Earlier versions described the data as simulated, which was wrong.

Suggested analyses.

  • a proportional odds (cumulative logit) model of satisfaction on income and gender, with cumulative odds ratios and cut-points;

  • checking the proportional odds assumption, for example by comparing binary logits for satisfaction >= 2, >= 3 and >= 4;

  • income as a linear score versus a factor, compared with a likelihood-ratio test;

  • cumulative logit versus probit links.

See also

womenlf, and osentoff in disc, for other ordinal outcomes; codebook() and list_datasets(). The original 104-case table is on CRAN as coin::jobsatisfaction.

Examples

head(satisfaction)
#> # A tibble: 6 × 3
#>   gender income satisfaction
#>   <chr>   <int>        <int>
#> 1 F           1            1
#> 2 F           2            1
#> 3 F           3            1
#> 4 F           4            1
#> 5 M           1            1
#> 6 M           2            1
with(satisfaction, table(income, satisfaction))
#>       satisfaction
#> income  1  2  3  4
#>      1  2  4 13  3
#>      2  3  6 22  4
#>      3  2  2 15  8
#>      4  2  3 13  8

# Proportional odds model (requires the MASS package)
if (requireNamespace("MASS", quietly = TRUE)) {
  fit <- MASS::polr(factor(satisfaction) ~ income + gender,
                    data = satisfaction, Hess = TRUE)
  summary(fit)
}
